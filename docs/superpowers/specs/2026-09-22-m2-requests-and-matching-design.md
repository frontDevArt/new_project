## Общие ограничения (действуют без изменений с M0)

- Схема базы меняется **только** новой версионированной миграцией в `listam/migrations/`.
- Новый метод порта — это новый контрактный тест в `tests/contracts/`.
- Ни один путь, ключ, идентификатор и имя адаптера не зашит в код: внешнее — за портом,
  выбор — в конфиге, секреты — только в `.env`, подключение — в `listam/wiring.py`.
- Все отметки времени в UTC, пути относительные от корня проекта.
- **Пороги в конфиге не поднимаются, чтобы тест позеленел.** Порог, который мешает, —
  это либо находка, либо решение; и то и другое записывается, а не обходится.
- Ноль в пороге значит «ноль», а не «выключено»; выключается `null`.
- Бессмысленный ввод отклоняется на входе с кодом возврата 2, а не истолковывается.
- Тесты — только `.venv/Scripts/python.exe -m pytest -q`; прогон CLI из скрипта — только
  с `PYTHONIOENCODING=utf-8`.
- Телефоны (`contacts`) — M4, уведомления — M3. Не трогаем.

## Принятые решения (в фазах не пересматриваются)

1. **Нормализация заявки живёт в домене, а не в адаптере.** Порт `RequestsSource`
   отдаёт сырые строки (`rows()`), доменный разбор превращает их в `Request`.
   Иначе каждый адаптер нормализует по-своему, и контрактный тест перестаёт
   что-либо гарантировать: `csv` и `gsheet` обязаны давать одну и ту же заявку
   из одной и той же строки.
2. **Непонятная заявка отклоняется целиком и не роняет чтение.** Одна опечатка
   в бюджете не имеет права оставить брокера без остальных сорока девяти заявок
   и не имеет права быть истолкованной. Отклонённые перечисляются с причинами,
   код возврата 0 с пометкой `⚠` — расписание не падает из-за опечатки,
   `doctor` показывает их число. В базу отклонённая заявка не пишется.
3. **Этажные правила — отдельные колонки, а не строка `floor_rules`.**
   `floor_min`, `floor_max`, `no_first_floor`, `no_last_floor` читаются скорингом
   без разбора свободного текста. `floor_rules` остаётся человеческой заметкой.
4. **Объявление без улицы в кластер не сливается.** Улицы нет у 20% базы; ключ без
   неё вырождается в «район + комнаты + площадь ±2 + этаж», и разные квартиры
   одного дома склеятся в один кластер. Ложное слияние **прячет от клиента
   реальный вариант** — это дороже, чем второй звонок по той же квартире.
5. **Допуск ±2 м² — объединение, а не бакет.** Округление площади до бакета рвёт
   пару 99,9 / 100,1 и склеивает 98,0 / 100,0 по-разному в зависимости от границы.
   Внутри группы с одинаковыми район, улица, комнаты, этаж и этажность площади
   сортируются, и соседние, различающиеся не больше чем на порог, объединяются.
   Результат детерминированный и не зависит от порядка чтения базы.
6. **Выгодность считается против медианы района, а не кластера.** Спека называет
   медиану кластера, но в кластере 1–3 объявления: медиана по ним — это цена
   самого объявления, и фактор весом 20 превращается в шум. Медиана $/м² по
   району уже считается в `domain/stats.py` и уже выкидывает аномалии.
   Кластер остаётся единицей показа и дедупа, но не меркой цены.
7. **Матч, которого коснулся человек, пересчётом не затирается.** `status`
   (`sent`, `called`, `rejected`) и `reject_reason` — это след звонка, а не
   вычисленное значение. Пересчёт обновляет балл, разбор балла и поля кластера;
   статус и причину отказа не трогает.
8. **Матч на ушедшее объявление не удаляется.** «Мы звонили по этой квартире»
   должно переживать снятие объявления с ленты. В витрине такой матч помечается,
   а не исчезает.
9. **`scrape` в M2 не меняется.** Связка «новое объявление → заявки» делается
   отдельной командой `match --new` с окном последнего прогона. Краулер на
   864 строки — не место для движка скоринга, а расписание `scrape && match --new`
   даёт ровно то же поведение и проверяется по частям.
10. **Веса и пороги скоринга — секция `match` конфига.** Значения берутся из спеки
    (30/20/20/15/10/5, пороги 70 и 40) и в код не зашиваются. Правило «пороги не
    поднимаются ради зелени» на них распространяется с первого дня.
11. **`gsheet` пишется сразу, проверяется позже.** Креденшлов нет, живьём адаптер
    не проверить; контрактный тест — под `skipif`, как уже сделано для `gdrive`.
    Откладывать нельзя: Google Sheet назван в M2 прямо. Боевая приёмка M2 идёт
    на `csv`, и это записывается как ограничение приёмки, а не как проверенный факт.

## Архитектура

```
источник заявок              домен                        база
─────────────────            ─────                        ────
RequestsSource.rows()   →    requests.parse_rows()    →   requests
  csv | gsheet | none          Request, RequestError
                                      ↓
listings (активные)     →    clustering.assign()      →   listings.cluster_id
                                      ↓
                             stats.median_by_district
                                      ↓
                             scoring.score()          →   matches
                               Score(value, breakdown,
                                     rejected_by)
```

Новых модулей домена три: `listam/domain/requests.py` (разбор и нормализация строк),
`listam/domain/clustering.py` (кластеры), `listam/domain/scoring.py` (баллы).
Каждый — чистые функции без базы и без сети. Оркестрация — `listam/matching.py`
по образцу `listam/changes.py`: собирает выборку, зовёт домен, пишет результат.

## Модель заявки

Колонки источника, они же колонки таблицы `requests`:

| Колонка | Тип в источнике | Смысл |
| --- | --- | --- |
| `id` | текст | внешний идентификатор строки, ложится в `requests.external_id` |
| `client_name` | текст | имя покупателя |
| `client_phone` | текст | телефон покупателя |
| `status` | `active` / `paused` / `closed` | матчатся только `active` |
| `budget_max` | число USD | потолок бюджета |
| `budget_stretch` | число USD | растянутый потолок; пусто — `budget_max` плюс 10% |
| `districts` | список через запятую | допустимые районы; пусто — район не ограничен |
| `districts_priority` | список через запятую | приоритетные районы, подмножество `districts` |
| `rooms` | `2,3` или `2-3` | допустимое число комнат |
| `area_min`, `area_max` | число м² | диапазон площади |
| `floor_min`, `floor_max` | целое | диапазон этажа |
| `no_first_floor`, `no_last_floor` | да/нет | штраф за первый и последний этаж |
| `must_have`, `nice_to_have` | текст | пожелания; в M2 не скорятся, хранятся |
| `notes`, `floor_rules` | текст | человеческие заметки |

Разбор нестрогий по форме и строгий по смыслу: пробелы и регистр не важны, `да`/`нет`,
`yes`/`no`, `1`/`0`, `+`/`-` читаются одинаково, `1 200 $` и `1200` — одно число. Но
`budget_max = «примерно 100к»`, `rooms = «много»`, `area_min > area_max`,
`budget_stretch < budget_max`, неизвестный `status` — это отказ строки с текстом,
называющим колонку и значение.

## Дедуп кластеров

Ключ: район плюс нормализованная улица, комнаты, этаж, этажность; затем объединение
по площади с допуском `match.cluster.area_tolerance`, по умолчанию 2 м².
Нормализация улицы: регистр, лишние пробелы, отбрасываются «ул.», «улица», «փող.».
Объявление без улицы, без района или без площади получает кластер из самого себя.

`cluster_id` — устойчивый хэш канонического ключа группы: район, улица, комнаты,
этаж, этажность и границы объединённого диапазона площадей. Пересчитывается целиком
командой `listam cluster` и автоматически перед матчингом, если в выборке есть
объявления без `cluster_id`.

Единица показа — кластер: в витрине матч показывается один раз, по **самому дешёвому**
объявлению кластера, с пометкой «N объявлений, разброс $X». Единица записи в `matches` —
это объявление-представитель; остальные члены кластера матчей не порождают.

## Движок скоринга

**Жёсткие критерии** — отказ без балла, причина записывается в `rejected_by`:
район не из списка заявки; комнат меньше минимума заявки; цена выше `budget_stretch`;
площадь ниже `area_min`. Объявление со `status='gone'` или с меткой `anomaly`
в матчинг не попадает вовсе.

**Факторы и веса** — секция `match.weights`, значения по умолчанию из спеки:

| Фактор | Вес | Логика |
| --- | --- | --- |
| `budget` | 30 | в `budget_max` — полный балл, между `budget_max` и `budget_stretch` — убывает линейно до нуля |
| `district` | 20 | приоритетный район — полный балл, просто допустимый — половина |
| `price_per_sqm` | 20 | относительно медианы района: ниже медианы — выше балл, насыщение на −25% |
| `area_rooms` | 15 | попадание в `area_min`…`area_max` и в список комнат |
| `floor` | 10 | штраф за первый и последний, если заявка их не хочет; выход за `floor_min`…`floor_max` |
| `seller_type` | 5 | собственник — полный балл, агентство — ноль |

Фактор, для которого не хватает данных — нет `price_per_sqm`, нет медианы района,
у заявки не задан диапазон, — **не штрафуется и не награждается**: его вес исключается
из знаменателя. Балл — доля набранного от суммы весов применимых факторов, округлённая
до целого 0–100. Так заявка без диапазона площади не получает систематически меньший
балл, чем заявка с диапазоном.

Разбор балла (`breakdown`) пишется в `matches` как JSON: фактор — набрано и вес.
Без него «почему 68, а не 71» не ответить ни в отладке, ни клиенту.

**Пороги** — секция `match.thresholds`: `hot: 70` — немедленное уведомление, сработает
на M3; `digest: 40` — дневной дайджест. Ниже — только в базе. В M2 пороги влияют
на витрину и на счётчики, уведомлений ещё нет.

## Миграция 007

Единственная правка схемы, версия 6 → 7.

- `requests`: `districts_priority`, `floor_min`, `floor_max`, `no_first_floor`,
  `no_last_floor`, `updated_at`, `source_row` — сырая строка источника, чтобы
  спорную заявку можно было предъявить как есть.
- `matches`: `run_id`, `breakdown`, `cluster_id`, `cluster_size`, `cluster_spread_usd`,
  `first_matched_at` — когда матч появился впервые; `matched_at` двигается пересчётом.
- `runs`: `new_matches` — счётчик, названный в спеке и до сих пор не заведённый.
- Индексы: `matches(request_id, score)`, `matches(listing_id)`, `listings(cluster_id)`,
  `listings(status, district)`.

## Порты и адаптеры

| Порт | Что меняется | Контрактный тест |
| --- | --- | --- |
| `RequestsSource` | `rows()` и `describe()`; `active_requests()` реализуется в базовом классе через `rows()` и доменный разбор | новый `tests/contracts/test_requests_source_contract.py`, параметризованный `none`, `csv`, `gsheet` под `skipif` |
| `Database` | `upsert_request`, `iter_requests`, `set_cluster_ids`, `upsert_match`, `matches_for_request`, `set_match_status`, `listings_for_matching` | дополняется `tests/contracts/test_database_contract.py` |
| `Exporter` | `export_matches` — лист «Матчи» | дополняется `tests/contracts/test_exporter_contract.py` |

Конфиг получает секцию `match` и наполнение секции `requests`:

```yaml
requests:
  kind: csv                     # none | csv | gsheet
  path: ./data/requests.csv     # для kind: csv
  # sheet: ${REQUESTS_SHEET}    # для kind: gsheet
  # credentials_file: ${GDRIVE_CREDENTIALS_FILE}

match:
  weights: {budget: 30, district: 20, price_per_sqm: 20, area_rooms: 15, floor: 10, seller_type: 5}
  thresholds: {hot: 70, digest: 40}
  budget_stretch_percent: 10    # если заявка не задала budget_stretch
  cluster: {area_tolerance: 2}  # м², допуск объединения площадей
  limit: 50                     # сколько строк показывает `matches`
```

## Команды

| Команда | Что делает |
| --- | --- |
| `listam requests` | читает источник, показывает разобранные и отклонённые заявки, записывает разобранные в базу |
| `listam cluster` | пересчитывает `cluster_id` по всей базе, печатает сводку: кластеров, из них многочленных, крупнейший |
| `listam match --request <id>` | новая заявка по всей активной базе |
| `listam match --new` | объявления с начала последнего прогона по всем активным заявкам |
| `listam match --all` | полный пересчёт всех активных заявок по всей базе |
| `listam matches [--request <id>] [--limit N] [--min-score N]` | ранжированная витрина матчей |
| `listam export` | плюс лист «Матчи» в `.xlsx` |
| `listam doctor` | плюс проверка источника заявок и секции `match` |

Взаимоисключающие флаги `match` разбираются на входе: два сразу — код возврата 2,
ни одного — тоже код 2 с подсказкой. `--request` на несуществующую или неактивную
заявку — код 2 с внятным текстом.

Расписание в README становится `scrape --fresh && match --new` раз в час и
`scrape && match --all` раз в сутки.

## Ошибки и отказы

| Ситуация | Поведение |
| --- | --- |
| Источник заявок недоступен | код 1, база не трогается |
| Часть заявок не разобрана | остальные записываются, отклонённые перечислены, код 0 с `⚠` |
| Все заявки не разобраны | код 1: это не опечатка, это уехавший формат таблицы |
| Активных заявок ноль | `match` печатает «заявок нет» и выходит с кодом 0 |
| Схема базы младше 7 | код 1 с указанием накатить миграции, как уже делают `changes` и `export` |
| У объявления нет цены | жёсткий критерий бюджета пропустить нельзя: объявление не матчится, причина записывается |

## Приёмка M2

1. Заведена реальная заявка в `csv`, прочитана `listam requests`, лежит в базе.
2. `listam cluster` прошёл по боевой базе: сводка по кластерам предъявлена,
   доля объявлений без улицы названа отдельно.
3. `listam match --request <id>` по 20 826 объявлениям дал ранжированный список;
   верхние пять проверены руками — балл объясним разбором.
4. `listam match --new` после инкрементального прогона нашёл матчи только среди
   новых объявлений.
5. Пересчёт идемпотентен: второй `match --all` не создаёт дублей и не затирает
   статус, проставленный человеком.
6. `.xlsx` содержит лист «Матчи», `doctor` зелёный, батарея прошла целиком.

## Что в M2 не входит

- Уведомления и дайджест (M3), телефоны продавцов (M4), дашборд (M5).
- Обратная связь клиента, сужающая будущие матчи: поле `reject_reason` заводится
  и заполняется руками, автоматики по нему в M2 нет.
- Скоринг `must_have` и `nice_to_have` свободным текстом: поля хранятся, но не
  участвуют в балле — иначе понадобится разбор человеческого языка, а это не M2.
- Аренда и другие категории: парсер прежний.
- Живая проверка `gsheet`: адаптер пишется, приёмка идёт на `csv` (решение 11).
