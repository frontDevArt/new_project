# Переезд на Linux-сервер

Цель: listam работает на Linux-сервере сам, по расписанию, и Windows-машину
больше не нужно держать включённой. Делать **после приёмки M3.5**
(72 часа заканчиваются 26.09.2026 в 22:00). Если переехать посреди замеров,
приёмка оборвётся.

Код к переезду уже готов, переписывать ничего не нужно:

* `schedule install` на Linux пишет строки в `crontab`, а не задачи `schtasks`
  (`listam/schedule.py`);
* `schedule.linux_xvfb: true` запускает каждый цикл под `xvfb-run -a`, так
  браузер с окном работает на сервере без экрана;
* расписание задано по `locale.timezone` (Asia/Yerevan), а в `crontab` оно
  пишется уже во времени сервера;
* база — это один файл SQLite, его можно просто скопировать.

## Главный риск — Cloudflare

list.am пропускает только настоящий браузер с окном (раздел «Как обходится
Cloudflare» в `docs/устройство.md`). Дома у Windows-машины обычный IP
провайдера. У облачного сервера IP датацентра, и Cloudflare проверяет такие
адреса жёстче. Может получиться, что на Windows всё работает, а на VPS каждая
страница отдаёт 403. Заранее это не узнать, поэтому **шаг 1 — проверка на
арендованном на час сервере**, до всякого переезда.

## Куда переезжать

| Вариант | Cloudflare | Цена | Примечание |
| --- | --- | --- | --- |
| VPS за границей (Hetzner, DigitalOcean и т.п.) | риск 403 | ~5 €/мес | 2 vCPU, 2 ГБ RAM минимум: Chromium с окном ест память |
| VPS армянского хостинга | лучше: местный IP | дороже | list.am армянский сайт, местный IP вызывает меньше подозрений |
| Мини-ПК или Raspberry Pi дома, Linux | как сейчас: домашний IP | разовая покупка | 5–10 Вт вместо включённого Windows; не облако, но задачу решает |
| VPS + residential proxy | как дома | + плата за прокси | запасной план, если VPS режут |

Не подходит: serverless (GitHub Actions, Cloud Run и т.п.). У приложения
локальная база, профиль браузера и замок прогона, и всё это должно жить
между запусками.

Выбор по результату шага 1: все страницы отдают 200 — берём VPS за границей;
403 — армянский хостинг, мини-ПК дома или прокси.

## Чек-лист

### Шаг 1. Проверка Cloudflare (≈1 час, до переезда)

- [ ] Арендовать VPS: Ubuntu 24.04, 2 vCPU, 2 ГБ RAM (почасовая оплата).
- [ ] Поставить системные пакеты:
  ```bash
  sudo apt update && sudo apt install -y git python3-venv xvfb
  ```
- [ ] Забрать код и поставить зависимости:
  ```bash
  git clone https://github.com/frontDevArt/new_project.git listam && cd listam
  python3 -m venv .venv
  .venv/bin/pip install -r requirements.txt
  .venv/bin/playwright install --with-deps chromium
  ```
- [ ] Прогнать пробный обход. База не создаётся, сообщения в Telegram не
  уходят, `.env` не нужен:
  ```bash
  xvfb-run -a .venv/bin/python -m listam scrape --max-pages 5 --dry-run
  ```
- [ ] Посмотреть итог:
  * 5 страниц разобраны, карточки есть — **Cloudflare пропускает**, VPS подходит;
  * 403, «проверка Cloudflare», «меньше `min_cards_per_page` карточек» —
    **режут**. Повторить один раз через 10 минут (проверка бывает капризной
    на первом заходе). Снова 403 — этот сервер не годится.
- [ ] Удалить пробный VPS, если он не подошёл.

### Шаг 2. Подготовка сервера (на выбранном сервере)

- [ ] Завести обычного пользователя, не работать под `root`:
  ```bash
  sudo adduser listam && sudo usermod -aG sudo listam
  ```
- [ ] Поставить часовой пояс Еревана, чтобы время в логах совпадало с
  расписанием:
  ```bash
  sudo timedatectl set-timezone Asia/Yerevan
  ```
- [ ] Под пользователем `listam` повторить установку из шага 1: `apt`, `git clone`,
  `venv`, `pip install`, `playwright install --with-deps chromium`.
- [ ] Прогнать тесты:
  ```bash
  .venv/bin/python -m pytest -q
  ```

### Шаг 3. Остановить Windows (боевая машина DESKTOP-79NF3LJ)

Две машины **не должны работать одновременно**: обе пошлют брокеру в
Telegram одно и то же, и две копии базы разойдутся. Замок прогона
(`listam.lock`) защищает только внутри одной машины.

- [ ] Дождаться, пока не идёт ни один цикл: в `data/logs` нет свежего лога
  без итога, рядом с базой нет `listam.lock`.
- [ ] Снять задачи планировщика:
  ```bash
  .venv/Scripts/python -m listam --env prod schedule remove
  ```
- [ ] Проверить, что задач `listam` в планировщике Windows больше нет
  (`schtasks /query | findstr listam` ничего не выводит).

### Шаг 4. Перенести данные

Эти файлы не лежат в git (`.gitignore`), их нужно скопировать руками, например
через `scp` или WinSCP. Путь на Windows: `C:\Users\Admin\Downloads\list`.

- [ ] `data/store/` — целиком: боевая база `listam-prod.sqlite` и бэкапы.
- [ ] `data/listam-prod.sqlite` — рабочая копия базы.
- [ ] `data/requests.csv` — заявки покупателей.
- [ ] `.env` — токен бота и чат (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`).
- [ ] **Не копировать** `data/browser/`: куки Cloudflare привязаны к IP и
  браузеру, на новом сервере они не подойдут. Профиль создастся заново.
- [ ] **Не копировать** `.venv/`: он собран под Windows.
- [ ] На сервере закрыть `.env` от чужих глаз:
  ```bash
  chmod 600 .env
  ```

### Шаг 5. Проверить на сервере

- [ ] Самопроверка без строк «СБОЙ»:
  ```bash
  xvfb-run -a .venv/bin/python -m listam --env prod doctor
  ```
- [ ] Короткий настоящий обход:
  ```bash
  xvfb-run -a .venv/bin/python -m listam --env prod scrape --fresh
  ```
- [ ] Дайджест вхолостую, без отправки:
  ```bash
  .venv/bin/python -m listam --env prod notify --digest --dry-run
  ```

### Шаг 6. Включить расписание

- [ ] Посмотреть, что будет поставлено:
  ```bash
  .venv/bin/python -m listam --env prod schedule show
  ```
  Ожидается три строки: `hourly` (каждый час), `nightly` (04:30),
  `evening` (20:30), все с `xvfb-run -a` и меткой `# listam:`.
- [ ] Поставить:
  ```bash
  .venv/bin/python -m listam --env prod schedule install
  ```
- [ ] Проверить:
  ```bash
  crontab -l
  ```

### Шаг 7. Первые сутки

- [ ] Через час: в `data/logs` появился лог `hourly`, в нём нет ошибок.
- [ ] В 20:30: брокеру пришёл вечерний дайджест, **один**, без дубля.
- [ ] Утром после 04:30: ночной полный обход прошёл, страниц примерно столько
  же, сколько на Windows (~215).
- [ ] Тревог о сбоях в чат не было.
- [ ] Всё зелёное — Windows-машину можно выключать. Папку `list` на ней
  пока не удалять: это резервная копия на случай отката.

## Откат

Если на сервере не взлетело:

1. На сервере: `.venv/bin/python -m listam --env prod schedule remove`.
2. Если сервер успел поработать, скопировать `data/store/` и
   `data/listam-prod.sqlite` с сервера обратно на Windows, иначе потеряются
   его прогоны и журнал отправок.
3. На Windows: `.venv/Scripts/python -m listam --env prod schedule install`.

## Если что-то пошло не так

| Симптом | Что делать |
| --- | --- |
| Все страницы 403 | IP датацентра режут: армянский хостинг, мини-ПК дома или residential proxy |
| Первая страница 200, дальше 403 | Проверить, что `scrape.headless: false` и что запуск идёт под `xvfb-run` |
| Прогон падает по памяти, Chromium убит | Сервер с 2 ГБ RAM мал: взять 4 ГБ или добавить swap |
| Расписание срабатывает не в то время | Проверить `timedatectl`; после смены пояса повторить `schedule install` |
| Проверка Cloudflare снова и снова | Профиль протух: удалить `data/browser/`, он создастся заново |
| `playwright install` не качает Chromium | На сервере это редкость; если сеть режет `storage.googleapis.com` — ставить через зеркало (`PLAYWRIGHT_DOWNLOAD_HOST`) |
