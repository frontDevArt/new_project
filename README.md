# listam — мониторинг list.am под заявки покупателей

Инструмент брокера: копим объявления о продаже квартир, чтобы под заявку клиента
находить вариант первыми. Раз в час система сама проходит голову ленты
list.am, примеряет новое к заявкам и шлёт брокеру в Telegram «звони сейчас»;
ночью — полный обход, вечером — дайджест за день.

* Это руководство оператора: что запускать и что увидишь.
* Почему устроено так, все флаги команд и история этапов — `docs/устройство.md`.
* Спека и роадмап — `list.am → заявки покупателей MVP-спека и роадмап.md`;
  спеки этапов — `docs/superpowers/specs/`, планы — `docs/superpowers/plans/`.

Что приходит брокеру:

| Когда | Что | Команда |
| --- | --- | --- |
| раз в час | 🔥 «звони сейчас»: рыночные варианты от 80 баллов с прошлой отправки; пусто — сообщения нет | `notify --hot` |
| вечером, 20:30 | 📋 дайджест: сводка дня и сообщение на каждую заявку со звонками; первичная подборка новой заявки — отдельным разделом | `notify --digest` |
| ночью, 04:30 | 🗞 лента вне заявок: счётчики и 💎 — заметно дешевле медианы района | `notify --feed` |

## Быстрый старт

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt -r requirements-playwright.txt
.venv/Scripts/python -m playwright install chromium
cp .env.example .env
.venv/Scripts/python -m listam doctor
```

Окружение выбирается переменной `APP_ENV` (`dev` по умолчанию) или флагом `--env`.
Боевое — `--env prod`: рабочая копия базы `listam-prod.sqlite` в `data/`, общая
копия и бэкапы — в `data/store`; заявки у `dev` и `prod` общие — `data/requests.csv`.
Без `tzdata` из `requirements.txt` Windows не знает часовых поясов — `doctor`
скажет «СБОЙ Расписание».

Боевой запуск с нуля — по порядку, каждая команда с кодом 0:

```bash
cp config/requests.example.csv data/requests.csv                # вписать заявки
.venv/Scripts/python -m listam --env prod doctor                 # без строк «СБОЙ»
.venv/Scripts/python -m listam --env prod requests
.venv/Scripts/python -m listam --env prod scrape                 # полный обход: ~215 страниц, ~10 минут
.venv/Scripts/python -m listam --env prod match --all
.venv/Scripts/python -m listam --env prod notify --digest --dry-run
.venv/Scripts/python -m listam --env prod schedule install       # дальше система работает сама
```

Обход открывает окно браузера — так и должно быть (раздел «Как обходится
Cloudflare» в `docs/устройство.md`). Компьютер не должен спать.

## Команды

Все команды — `.venv/Scripts/python -m listam [--env prod] <команда>`.

| Команда | Что делает |
| --- | --- |
| `python -m listam doctor` | Самопроверка: конфиг, хранилище, схема, курс, Telegram, расписание, воронка, доступ к list.am. `--no-network` — без сети |
| `python -m listam scrape` | Полный обход ленты. `--fresh` — только голова ленты (часовой); `--resume` — продолжить оборванный; `--max-pages N`; `--dry-run` — без базы |
| `python -m listam scrape --allow-shrink` | Залить базу, хотя она заметно усохла; `--allow-upload-with-errors` — хотя в прогоне были ошибки |
| `python -m listam recheck` | Пересчитать пометки и суммы по всей базе после смены правил или схемы |
| `python -m listam export` | Выгрузка базы и листа «Матчи» в `.xlsx` |
| `python -m listam requests` | Перечитать заявки из таблицы брокера |
| `python -m listam cluster` | Пересчитать кластеры-дубли: одна квартира, выставленная тридцать раз, — один вариант |
| `python -m listam pages` | Воронка: открыть страницы кандидатов, не больше `funnel.max_opens_per_run`; `--dry-run`, `--max N`, `--keep-html` |
| `python -m listam match --all` | Подбор по всей базе под все активные заявки; `--new` — по тронутому с прошлого прогона; `--request R-1` — одна заявка |
| `python -m listam matches` | Витрина: лучший балл первым. `--request R-1`, `--new`, `--limit 20`, `--min-score 70` |
| `python -m listam find --district Арабкир --rooms 3 --max-price 120000` | Быстрый поиск без заявки; ничего не пишет |
| `python -m listam mark R-1 24254997 called` | След звонка; `rejected --reason "…"` — отказ, `new` — откат |
| `python -m listam notify --hot` | «Звони сейчас»; `--digest` — дайджест, `--feed` — лента вне заявок, `--dry-run` — показать и не слать |
| `python -m listam changes` | Что принёс последний прогон: новое, цены, снятое, вернувшееся. `--hours 24`, `--limit 20` |
| `python -m listam cycle hourly` | Выполнить цикл расписания руками, как планировщик |
| `python -m listam schedule show` | Что поставит `install`; `install` — поставить задачи, `remove` — снять свои |

Каждый флаг с объяснением — `docs/устройство.md`, «Команды целиком».

Бессмысленный ввод (`--max-pages 0`, `--limit 0`, `--min-score 120`, опечатка
в конфиге) — отказ на входе с кодом 2 и текстом, до базы и сайта дело не
доходит. Код 1 — ошибка прогона (она же в `runs.errors`, `runs.notes`).
Ноль в пороге конфига значит «ноль», выключает порог `null`.

**Команды, пишущие в базу, мигрируют базу сами:** `scrape`, `cluster`,
`requests`, `match`, `notify`, `pages`, `mark` и `recheck` берут замок,
забирают свежую копию из хранилища и накатывают миграции. Читающие —
`export`, `changes`, `matches`, `doctor` — на старой схеме отказывают;
тогда хватит любой пишущей команды или `python -m listam recheck`.

## Заявки покупателей

Заявки ведёт брокер во внешней таблице: `requests.kind: csv` (файл) или
`gsheet` (Google-таблица, настройка — в `docs/устройство.md`).
`python -m listam requests` читает её и кладёт в базу. Строка-образец со всеми
колонками — `config/requests.example.csv`. Для `csv`
скопируй его в `data/requests.csv` (папка `data/` не коммитится) и правь.

Колонок девятнадцать, порядок значения не имеет — колонки ищутся по именам
шапки:

| Колонка | Пример | Смысл |
| --- | --- | --- |
| `id` | `R-1` | идентификатор строки; по нему заявка узнаётся при перечитывании |
| `client_name` | `Ани` | имя покупателя |
| `client_phone` | `+374 00 000000` | телефон покупателя |
| `status` | `active` | `active`, `paused` или `closed`; матчатся только `active` |
| `budget_max` | `120 000 $` | потолок бюджета в USD |
| `budget_stretch` | `135000` | растянутый потолок; пусто — `budget_max` плюс `match.budget_stretch_percent` |
| `districts` | `Кентрон, Арабкир` | допустимые районы; пусто — район не ограничен |
| `districts_priority` | `Кентрон` | приоритетные районы, подмножество `districts` |
| `rooms` | `2-3` или `2,3` | допустимое число комнат |
| `area_min` | `60` | нижняя граница площади, м² |
| `area_max` | `95` | верхняя граница площади, м² |
| `floor_min` | `2` | нижняя граница этажа |
| `floor_max` | `` | верхняя граница этажа; пусто — не ограничена |
| `no_first_floor` | `да` | первый этаж клиенту не нужен |
| `no_last_floor` | `нет` | последний этаж клиенту не нужен |
| `must_have` | `ремонт` | обязательные пожелания через запятую — слова из словаря `funnel.wishes`; неизвестное слово — отказ строки (раздел «Воронка») |
| `nice_to_have` | `балкон` | желательные пожелания; неизвестное слово — предупреждение, заявка читается |
| `floor_rules` | `не первый и не последний` | человеческая заметка про этажи; скорингом не читается |
| `notes` | `звонить после 18` | заметка для себя |

* Пробелы, регистр и знак валюты не важны: `1 200 $` = `1200`, `да`/`yes`/`1`/`+`
  — одно «да». Но «примерно 100к», `area_min > area_max` или неизвестный
  `status` — отказ строки с названной колонкой; остальные строки читаются,
  отчёт пишет `⚠ Не разобрано: N`.
* Запятая внутри значения — в кавычках: `"семья с ребёнком, смотрит с октября"`.
* Строку удалили из таблицы — заявка закрывается («закрыты (нет в источнике)»);
  её матчи и след звонка остаются в базе. Пустая таблица не закрывает ничего —
  это сбой доступа, а не «все ушли».

## Подбор и витрина

Одна квартира, выставленная несколько раз, — один кластер и один матч на
самое дешёвое объявление; в витрине: «3 объявления, разброс $11 000».
Район не из заявки, комнат меньше минимума, цена выше растянутого бюджета,
площадь ниже `area_min`, слово `must_have`, которому страница не подходит, — в матчи
не попадает. Остальное получает балл 0–100 по весам `match.weights`:
выгодность цены за метр против медианы района 40, район 20 (приоритетный —
полный), площадь и комнаты 15, пожелания `nice_to_have` 15, бюджет 10, этаж 10,
собственник 5. Фактор без данных из счёта выпадает: идеальное попадание — 100.

* `match.thresholds.hot: 80` — «звони сейчас»; `match.thresholds.digest: 40` —
  ниже этого в витрину и дайджест не попадает. Флаги `matches --min-score`
  и `--limit` переопределяют порог и число строк (`match.limit`).
* `match --new` берёт появившееся, вернувшееся и **сменившее цену** с начала
  прошлого прогона, а правленую заявку — по всей базе. Закрывает матчи
  только `match --all`: «Закрыто матчей: N — вариант больше не подходит».
  Закрытый матч остаётся в базе со следом звонка; снятое с ленты помечается
  в витрине, а не исчезает.
* Лист «Матчи» в `.xlsx` — не больше `export.matches_limit` (200) строк на заявку.

## Воронка: страницы объявлений

Ремонт, тип дома, лифт и балкон есть только на странице объявления.
Страницы открываются **только у кандидатов**: прошли грубое сито живой
заявки с пожеланиями и могут стать горячими. Лучшие первыми, с паузой
`funnel.delay_seconds` (5 с), не больше `funnel.max_opens_per_run` (30) за
прогон; открытое ложится в кэш `listing_pages` и повторно открывается,
только когда объявление изменилось. Часовой и ночной циклы зовут `pages` сами;
`pages --dry-run` покажет очередь, не трогая сайт.

Слова пожеланий — словарь `funnel.wishes` в конфиге; слово в заявке, которого
нет в словаре, в `must_have` — отказ строки, в `nice_to_have` — ⚠:

```yaml
funnel:
  wishes:
    ремонт:     {field: renovation, any_of: [косметический, евроремонт, дизайнерский]}
    не панель:  {field: building_type, none_of: [панельное]}
    балкон:     {field: balcony, is: true}
    высокие потолки: {field: ceiling_height, min: 3}
```

* `must_have` — жёсткий критерий: поле не подходит — отказ; страницы ещё
  нет — объявление кандидат, матч родится после открытия и придёт в «звони
  сейчас» как новый; поля на странице нет — не отказ, брокер уточнит звонком.
* `nice_to_have` — фактор балла `wishes`.
* Новая или правленая заявка получает **первичную подборку**: её сотни матчей
  идут не в «звони сейчас», а в вечерний дайджест разделом «📋 ДАЙДЖЕСТ · R-4 ·
  Клиент — первичная подборка: 15 лучших из 495» (`notify.digest.initial_top`).

## Быстрый поиск: `find`

«Арабкир, 3 комнаты, до $120k» — одной командой, без строки в таблице:

```bash
.venv/Scripts/python -m listam find --district Арабкир --rooms 3 --max-price 120000
```

Флаги — это колонки заявки: `--district` (повторяется), `--rooms 2-3`,
`--max-price`, `--area 80-110`, `--not-first-floor`, `--not-last-floor`,
`--wish "евроремонт, лифт"`; ещё `--owner` и `--limit`. Балл — тот же, что
у подбора. Заявку, матчи и след звонка `find` не пишет; без `--open` читает базу без замка, посреди прогона.
`--open N` открывает страницы N лучших найденных (не больше
`funnel.find_max_opens`, 20) и идёт на сайт — под замком, как `pages`.

## Отметки и отказы: `mark`

След звонка пишет только человек — этой командой. Подбор его не трогает.

```bash
.venv/Scripts/python -m listam mark R-1 24254997 called
.venv/Scripts/python -m listam mark R-1 24254997 rejected --reason "первый этаж"
.venv/Scripts/python -m listam mark R-1 24254997 rejected --reason "район, дорого"
.venv/Scripts/python -m listam mark R-1 24254997 new
```

* Номер — объявление, по которому звонил; матч найдётся и на дешёвом
  двойнике той же квартиры.
* `rejected` исключает эту квартиру из заявки **всегда**. Слова причины из
  `feedback.reasons` — «первый этаж», «последний этаж», «район», «тип дома»,
  «ремонт» — сужают заявку в базе (таблицу брокера никто не перезаписывает);
  остальные слова записываются и заявку не сужают — команда так и скажет.
* `new` — откат: статус и причина стёрты, исключения этой отметки сняты.
* Следом идёт подбор по заявке: отпавшее закрывается «клиент отказал: …»,
  а шапка заявки в сообщениях говорит «… · без 1-го этажа, без панели».

## Telegram: уведомления и дайджест

Канал — `notify.kind: telegram`, токен и чат — в `.env`
(`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`); без них работает всё, кроме
отправки. Каждая заявка — отдельным сообщением (брокер пересылает его
клиенту); длинное режется между карточками, продолжение — с шапкой заявки.
Окно считается от прошлой отправки: повторный запуск не шлёт то же второй раз,
сбой канала ничего не теряет. `--dry-run` печатает то же и журнал не трогает.

### Как выглядит сообщение

«Звони сейчас» (`notify --hot`):

```
🔥 ЗВОНИ СЕЙЧАС · R-4 · Клиент 4
Канакер-Зейтун · 2 комн. · 80–110 м² · до $175 000
━━━━━━━━━━━━━━━

🆕 $165 000 · 100 м² · $1 650/м² (−12% к району)
📍 Канакер-Зейтун, ул. Азатутян · этаж 5/9
👤 Собственник · 🟢 балл 82 · 🔗 Открыть

📉 $158 000 (было $171 000) · 95 м² · $1 663/м²
📍 Канакер-Зейтун, ул. Раффи · этаж 3/12
🏢 Агентство · 3 объявления, разброс $8 000 · 🟢 балл 78 · 🔗 Открыть

➕ ещё 12 вариантов — в дайджесте вечером
```

Дайджест (`notify --digest`) — первым сообщением сводка («🆕 новых — 14
📉 подешевело — 3», строка на заявку, «❌ 1 (бюджет 1)» — что отпало и почему),
затем по сообщению на заявку со звонками, в том же формате. Лента
(`notify --feed`) — счётчики за сутки и 💎 самые выгодные против медианы
района. Примеры обоих — в `docs/устройство.md`.

Значки: 🆕 новое · 📉 подешевело (с прежней ценой) · ♻️ вернулось на ленту ·
❌ снято или отпало · 👤 собственник · 🏢 агентство · балл 🟢 от 90, 🟡 от 80,
⚪ ниже · 💎 заметно дешевле медианы района · ⚠️ заявка слишком широкая ·
➕ сколько не вошло. Процент в скобках — цена за метр против медианы района.
На заявку — `notify.<вид>.per_request` лучших и хвост «➕ ещё N».

## Как запускать по расписанию

Своего демона у `listam` нет: задачи системному планировщику пишет
`schedule install`, а шаги берутся из конфига.

```yaml
schedule:
  cycles:
    hourly:  {every_minutes: 60, steps: ["scrape --fresh", "pages", "match --new", "notify --hot"]}
    nightly: {at: "04:30", steps: ["scrape", "pages", "match --all", "notify --feed"]}
    evening: {at: "20:30", steps: ["notify --digest"]}
```

* **Раз в час** — голова ленты, страницы кандидатов, подбор нового, «звони сейчас».
* **Ночью** — полный обход (только он помечает снятые), пересчёт всех
  матчей, лента вне заявок.
* **Вечером** — дайджест. Время `at` — в `locale.timezone` (Ереван).

Команды — с `--env prod`: `python -m listam schedule show` (что будет
поставлено, ничего не трогая), `python -m listam schedule install` (поставить;
повторно — переставить), `python -m listam schedule remove` (снять свои задачи),
`python -m listam cycle hourly` (цикл руками, как планировщик).

* **Работает ли** — `doctor`, строка «Расписание»: ⚠, если последний
  часовой старше 2 ч или полный старше 26 ч.
* **Лог** — `data/logs/cycle-ГГГГ-ММ-ДД.log`: шаги цикла, их вывод и коды.
  Первое, куда смотреть.
* **Сбой шага** — одна строка брокеру в чат («⚠️ listam: часовой цикл не
  прошёл…»), не чаще `schedule.alert_every_hours`.
* **Windows:** задачи `listam-hourly`, `listam-nightly`, `listam-evening`
  (проверить: `schtasks /query /tn listam-hourly /v /fo list`). Пользователь
  должен быть залогинен, компьютер — не спать («Электропитание» → сон
  «Никогда» при питании от сети).
* Расписание — **на одной машине**: две машины с задачами шлют брокеру
  каждое сообщение дважды.

## Переезд на другой аккаунт или хранилище

1. Скопировать файл базы (`storage.db_filename`; боевая — `listam-prod.sqlite`
   в `data/store`) в новое хранилище — база это один файл.
2. Заполнить `.env` новыми идентификаторами (образец — `.env.example`).
3. Переключить `storage.kind` в нужном `config/<env>.yaml`.
4. `APP_ENV=prod python -m listam doctor` — отчёт должен быть без строк «СБОЙ».

Google Drive (этап M3.6) — `docs/устройство.md`, «Переезд на Google Drive».

**На Linux** — после `git clone`, `pip install` и `playwright install`
(на старой машине сначала `schedule remove`):

```bash
cp .env.example .env            # и заполнить
.venv/bin/python -m listam --env prod schedule show
.venv/bin/python -m listam --env prod schedule install
```

`install` дописывает строки в `crontab` и заворачивает цикл в `xvfb-run -a`;
чужие строки не трогает. Посмотреть задачи Linux, не уезжая:
`schedule show --platform linux`.

## Тесты

```bash
.venv/Scripts/python -m pytest -q
```
